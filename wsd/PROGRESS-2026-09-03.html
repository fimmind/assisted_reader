Definition-ranking research: progress

Assisted Reader, checkpoint of September 3, 2026

Goal

The reader will continue to show every available definition. The experiment is only about ordering them: definitions clearly incompatible with the current context should appear lower. Choosing among close, defensible definitions is a smaller concern.

Current conclusion: the existing POS signal is valuable, but neither tested semantic encoder is ready to replace the POS-first baseline. The next experiments should focus on ranking definitions that share the same POS.

What was built

  • A standalone wsd/ benchmark workspace with repeatable download, preparation, validation, evaluation, and error-report scripts.
  • Normalized datasets: Raganato ALL (5,952 WordNet examples) and CoarseWSD-20 (10,196 examples, with 8,002 mapped to WordNet labels).
  • An approved reader-like development dataset: 28 contextual dictionary entries, 363 actual candidate definitions, with every candidate labelled fits, plausible, or clearly_wrong.
  • A self-contained clickable review page used to inspect the reader dataset. It remains available as reader-dev-v1-review.html.
  • Rankers for dictionary order, POS-first ordering, generic E5 embeddings, and the specialized WordNet sense-embedding model.

Important implementation correction

The first draft used a lemmatized form to find definitions. That could erase grammatical information: for example, interesting could be treated as the noun interest. The draft builder now uses the exact displayed word first and carries a contextual POS. The product itself already follows the same exact-word-first lookup policy.

What the numbers say

  • POS ordering alone substantially reduces obvious top-ranked mistakes.
  • The specialized model is much better than POS-order at separating acceptable from clearly wrong candidate pairs, but it still chooses the wrong top definition too often.
  • The remaining POS-first errors are largely same-POS ambiguities, including company, subject, rule, model, and letter.
  • The generic E5 retrieval formulation is currently weak as a top-1 ranker. It should remain a comparison point, not a product choice.

What remains

Do not overinterpret this yet. The approved reader data is a 28-example development set and has already guided decisions. It is not a final unbiased test set. A separate held-out reader test set is needed before choosing a production model.
  1. Evaluate the prepared CoarseWSD-20 diagnostic.
  2. Test ready-made direct ranking models next, beginning with Babelscape WSL Retriever, then one or two compact generic controls such as MiniLM/BGE.
  3. Run each model with and without POS-first ordering and inspect same-POS errors.
  4. Create and freeze a larger held-out reader-test-v1 before model selection.
  5. Only then investigate ONNX/browser size, latency, quantization, and production licensing.

Model status

  • intfloat/e5-small-v2: tested; compact generic encoder; not promising as top-1 ranker in the current formulation.
  • marksverdhei/wordnet-sense-embedding: tested; specialized gloss bi-encoder; promising pairwise behavior but not yet good enough at rank 1.
  • Babelscape/wsl-retriever-e5-base-v2: next direct candidate. It is WordNet-specific and larger; its published license is CC-BY-NC-SA-4.0, so it is research-only unless licensing changes.
  • PyMUSAS and similar semantic taggers: not direct gloss rankers, so they are lower priority.
